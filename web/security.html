Security

Security you can verify, not just read about.

TrailSeal exists to make agent activity provable, so its own foundations follow the same rule: this page lists what is built and running today, and says plainly what isn't.

What's in place

How your data is protected

Tamper-evident event chain

Every event is hash-linked to the one before it. If a past event is altered, every event after it fails verification, and a broken chain raises an internal alert every time.

Tenant isolation

Projects, API keys, agents, and events are scoped to a tenant at the database layer. Cross-tenant reads fail closed, not just hidden in the UI.

Scoped API keys

Keys carry a scope: ingest (write-only), read (read-only), or admin. A key is shown in full exactly once and stored only as a SHA-256 hash, so a lost key is revoked and reissued.

Account protection

Passwords are hashed with bcrypt (cost 12). Login is rate-limited per IP and email. Verification links last 24 hours, reset links 1 hour, and a password reset signs out existing sessions.

Role-based access

Owner, Admin, and Member roles. Only an Owner can touch billing, retention, or the danger zone.

Retention and deletion

Events are kept up to your plan's retention ceiling (14 days on Free, 180 on Pro). Deleting a tenant is a soft delete first, with a 30-day grace period on Free and Pro and 60 days on Business, before a permanent purge.

Straight answers

What we don't claim yet

  • TrailSeal is in early access. We have not published a third-party audit or compliance certification (such as SOC 2 or ISO 27001).
  • Role changes can take up to 15 minutes to reach an active session, because roles are read from the session token.
  • Payments run through Stripe Checkout, so payment details are entered on Stripe's pages.
Responsible disclosure

Found a vulnerability?

Email support@trailseal.dev with the steps to reproduce. Please give us reasonable time to fix the issue before sharing it publicly.
