The difference

Most audit logs catch edits.
Deletions walk away clean.

Tampering with a record breaks its hash, and any chained log will notice. But deleting the most recent records breaks nothing — what remains still links perfectly, end to end. That is exactly what an insider covering their tracks would do, and it is the case almost nobody checks for.

/v1/events/verify valid
0001 mcp.tool_call 07e385ea…93bd
0002 audit.append 2b88f401…c7e2
0003 agent.decision 9dc45e12…7a0f
Three events, three links, nothing out of place.
↓ Someone with database access deletes record 0003. No hash is altered. Nothing is edited.
/v1/events/verify broken
0001 mcp.tool_call 07e385ea…93bd
0002 audit.append 2b88f401…c7e2
0003 missing —
The remaining links are intact. TrailSeal fails it anyway.

TrailSeal records how far the chain was ever written, separately from the events themselves. A log that is shorter than its own history is not a valid log — however clean the part that's left looks.

How it works

From agent call to provable record,
in one hop

No SDK to install and no change to your agent's code. You point an MCP client at the gateway, and every call it makes becomes a record that can be checked later by anyone holding the log.

  1. 01

    Your agent calls a tool

    Claude Code, Claude Desktop, or any MCP client calls a tool, prompt, or resource — authenticated by a scoped API key, resolved straight to your tenant.

  2. 02

    The gateway writes the event

    The call is written once to the event chain, hash-linked to the event before it, before the result is returned to your agent.

  3. 03

    Anyone verifies the chain

    Check integrity via /v1/events/verify or the dashboard's Chain Integrity card — valid, broken with the exact event, or empty.

What's live today

Built for systems where
"trust me" isn't good enough

Everything below is running in production today — not a roadmap.

One command to connect

A native MCP gateway that speaks Tools, Prompts, and Resources. Point Claude Code, Claude Desktop, or any MCP client at it with a single command and a scoped API key — no SDK, no code change in the agent itself.

Isolation that holds under test

Projects, API keys, agents, and events are scoped to a tenant at the database layer, and cross-tenant reads fail closed rather than being hidden in the UI. Every path — API key, session, MCP, export — is covered by its own test.

Retention that keeps the proof

Old events age out on your plan's schedule, but purging them doesn't blind the chain: a signed checkpoint takes their place, so everything that remains stays verifiable. Deleting history is normally how audit logs lose their integrity.

Roles, quotas, and billing

Owner, Admin, and Member roles provisioned on upgrade, with billing and retention reserved for the Owner. Per-tenant quotas enforced at ingest, and upgrades go through checkout — no sales call, no manual approval.
